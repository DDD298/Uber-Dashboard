15. ADMIN DASHBOARD - TÀI LIỆU TOÀN BỘ HỆ THỐNG

15.1. CƠ SỞ DỮ LIỆU

15.1.1. BẢNG USERS (Người dùng)
TABLE users (
  clerk_id VARCHAR(255) PRIMARY KEY,
  name VARCHAR(255) NOT NULL,
  email VARCHAR(255) UNIQUE NOT NULL,
  avatar TEXT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
- Mục đích: Lưu trữ thông tin người dùng/khách hàng
- Quan hệ:
  + clerk_id -> rides.user_id (1-N): Một user có nhiều chuyến đi
  + clerk_id -> ratings.user_id (1-N): Một user có nhiều đánh giá

15.1.2. BẢNG DRIVERS (Tài xế)
TABLE drivers (
  id SERIAL PRIMARY KEY,
  clerk_id VARCHAR(255),
  first_name VARCHAR(255) NOT NULL,
  last_name VARCHAR(255) NOT NULL,
  email VARCHAR(255) UNIQUE NOT NULL,
  phone VARCHAR(20),
  profile_image_url TEXT,
  car_image_url TEXT,
  car_seats INTEGER DEFAULT 4,
  vehicle_type VARCHAR(50) DEFAULT 'Car',
  license_plate VARCHAR(50),
  rating DECIMAL(3,2) DEFAULT 5.0,
  rating_count INTEGER DEFAULT 0,
  average_rating DECIMAL(3,2) DEFAULT 5.0,
  approval_status VARCHAR(20) DEFAULT 'pending',
  status VARCHAR(20) DEFAULT 'pending',
  total_trips INTEGER DEFAULT 0,
  completed_trips INTEGER DEFAULT 0,
  cancelled_trips INTEGER DEFAULT 0,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
- Mục đích: Lưu trữ thông tin tài xế
- Trạng thái approval_status: pending, approved, rejected
- Trạng thái status: pending, active, inactive, suspended
- Quan hệ:
  + id -> rides.driver_id (1-N): Một tài xế có nhiều chuyến đi
  + id -> ratings.driver_id (1-N): Một tài xế nhận nhiều đánh giá

15.1.3. BẢNG RIDES (Chuyến đi)
TABLE rides (
  ride_id SERIAL PRIMARY KEY,
  origin_address TEXT NOT NULL,
  destination_address TEXT NOT NULL,
  origin_latitude DECIMAL(10,8),
  origin_longitude DECIMAL(11,8),
  destination_latitude DECIMAL(10,8),
  destination_longitude DECIMAL(11,8),
  ride_time INTEGER,
  fare_price DECIMAL(10,2) NOT NULL,
  final_price DECIMAL(10,2),
  payment_status VARCHAR(20) DEFAULT 'pending',
  payment_intent_id VARCHAR(255),
  driver_id INTEGER REFERENCES drivers(id),
  user_id VARCHAR(255) REFERENCES users(clerk_id),
  ride_status VARCHAR(20) DEFAULT 'pending',
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  cancelled_at TIMESTAMP,
  cancel_reason TEXT
);
- Mục đích: Lưu trữ thông tin chuyến đi
- Trạng thái ride_status: pending, confirmed, accepted, in_progress, completed, cancelled
- Trạng thái payment_status: pending, paid, failed, refunded
- Quan hệ:
  + user_id -> users.clerk_id (N-1)
  + driver_id -> drivers.id (N-1)
  + ride_id -> ratings.ride_id (1-1)

15.1.4. BẢNG RATINGS (Đánh giá)
TABLE ratings (
  id SERIAL PRIMARY KEY,
  ride_id INTEGER NOT NULL REFERENCES rides(ride_id),
  user_id VARCHAR(255) NOT NULL REFERENCES users(clerk_id),
  driver_id INTEGER NOT NULL REFERENCES drivers(id),
  stars INTEGER NOT NULL CHECK (stars >= 1 AND stars <= 5),
  comment TEXT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
- Mục đích: Lưu trữ đánh giá của khách hàng về tài xế
- Quan hệ:
  + ride_id -> rides.ride_id (1-1): Mỗi chuyến đi chỉ có 1 đánh giá
  + user_id -> users.clerk_id (N-1)
  + driver_id -> drivers.id (N-1)

15.1.5. BẢNG PROMO_CODES (Mã giảm giá)
TABLE promo_codes (
  id SERIAL PRIMARY KEY,
  code VARCHAR(50) UNIQUE NOT NULL,
  description TEXT,
  discount_type VARCHAR(20) NOT NULL,
  discount_value DECIMAL(10,2) NOT NULL,
  max_discount_amount DECIMAL(10,2),
  min_order_amount DECIMAL(10,2),
  usage_limit INTEGER,
  used_count INTEGER DEFAULT 0,
  start_date TIMESTAMP NOT NULL,
  end_date TIMESTAMP NOT NULL,
  is_active BOOLEAN DEFAULT true,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
- Mục đích: Lưu trữ mã giảm giá
- discount_type: percentage (phần trăm) hoặc fixed (số tiền cố định)

15.4. CÔNG NGHỆ SỬ DỤNG & ỨNG DỤNG CHI TIẾT

15.4.1. Next.js (App Router)
- Ứng dụng: Framework tổng thể quản lý Frontend & Backend.
- Chức năng cụ thể:
  + App Router: Phân chia các trang quản trị (/admin, /admin/users,...).
  + API Routes (Backend): Xây dựng hệ thống RESTful API trong thư mục /app/api.
  + Layout & Templates: Duy trì giao diện Sidebar và Header nhất quán giữa các trang.
  + Server vs Client Components: Tối ưu hóa việc render dữ liệu tĩnh trên Server và xử lý tương tác (Forms, Dialogs) trên Client.
- Ví dụ trong Project:
  + File `src/app/admin/layout.tsx` định nghĩa layout chung (Sidebar + Header) cho tất cả trang admin.
  + Thư mục `src/app/api/admin/users/route.ts` chứa các API endpoint để quản lý người dùng (GET, POST, PATCH, DELETE).
  + Khi bạn truy cập `/admin/drivers`, Next.js tự động load file `src/app/admin/drivers/page.tsx` và hiển thị trang quản lý tài xế.

15.4.2. React 19
- Ứng dụng: Xây dựng giao diện theo Component-based.
- Chức năng cụ thể:
  + Hooks: Sử dụng `useState`, `useEffect`, `useMemo` để xử lý logic nội bộ component.
  + Reusable Components: Chia nhỏ UI thành các khối (Table, Card, Button) để dễ bảo trì.
- Ví dụ trong Project:
  + Component `StatCard` (src/components/Dashboard/StatCard.tsx) được tái sử dụng 4 lần trên Dashboard để hiển thị tổng số người dùng, tài xế, chuyến đi và doanh thu.
  + Hook `useState` được dùng trong `DriverDetailsDialog` để quản lý trạng thái mở/đóng của dialog và dữ liệu form.
  + Hook `useEffect` trong `RevenueChart` để đảm bảo biểu đồ chỉ render sau khi component đã mount (tránh lỗi SSR).

15.4.3. Tailwind CSS
- Ứng dụng: Thiết kế giao diện nhanh và responsive.
- Chức năng cụ thể:
  + Utility-First: Stylings linh hoạt ngay trong `className`.
  + Responsive: Sử dụng các tiền tố `md:`, `lg:`, `sm:` để điều chỉnh layout cho máy tính, tablet và mobile.
  + Custom Theme: Định nghĩa bảng màu xanh lá đặc trưng của hệ thống.
- Ví dụ trong Project:
  + Trong `StatCard`, class `grid grid-cols-1 md:grid-cols-2 lg:grid-cols-4` tạo layout 1 cột trên mobile, 2 cột trên tablet, 4 cột trên desktop.
  + Class `bg-green-50 text-green-700` tạo màu nền và chữ xanh lá nhạt cho các thẻ thống kê.
  + Button sử dụng class `px-4 py-2 rounded-lg hover:bg-green-600` để tạo padding, bo góc và hiệu ứng hover.

15.4.4. TanStack Query (React Query)
- Ứng dụng: Quản lý trạng thái Server-side.
- Chức năng cụ thể:
  + useQuery: Tự động fetching và caching danh sách người dùng, tài xế, chuyến đi.
  + Mutation: Xử lý các thao tác POST, PATCH, DELETE (tạo, cập nhật, xóa) và tự động làm mới dữ liệu (Invalidate Queries) sau khi thành công.
  + Loading States: Hiển thị Skeleton hoặc Spinner tự động trong quá trình đợi API.
- Ví dụ trong Project:
  + Hook `useAdminDrivers()` trong `src/hooks/useAdmin.ts` sử dụng `useQuery` với queryKey `["admin-drivers", params]` để fetch danh sách tài xế. Khi params thay đổi (ví dụ: chuyển trang), React Query tự động gọi lại API.
  + Khi bạn xóa một tài xế bằng `useDeleteDriver()`, sau khi xóa thành công, hook tự động gọi `queryClient.invalidateQueries({ queryKey: ["admin-drivers"] })` để làm mới danh sách tài xế mà không cần reload trang.
  + Trong component `DriversPage`, biến `isLoading` từ `useAdminDrivers()` được dùng để hiển thị Skeleton loading khi đang fetch dữ liệu.

15.4.5. Zustand
- Ứng dụng: Quản lý trạng thái Client-side nhẹ.
- Chức năng cụ thể:
  + Sidebar State: Điều khiển trạng thái đóng/mở của thanh menu qua tham số `isOpen` và hàm `toggle()`.
  + Trạng thái Menu: Lưu trữ lựa chọn của người dùng trong phiên làm việc hiện tại.
- Ví dụ trong Project:
  + File `src/stores/useMenuSidebar.ts` định nghĩa store với state `isOpen` (boolean) và các hàm `toggle()`, `open()`, `close()`.
  + Trong component `AppSidebar`, khi người dùng click vào nút menu, hàm `toggle()` được gọi để đảo trạng thái sidebar từ mở sang đóng hoặc ngược lại.
  + State này được chia sẻ giữa `AppSidebar` và `DashboardHeader` mà không cần prop drilling hay Context phức tạp.

15.4.6. PostgreSQL (Neon DB)
- Ứng dụng: Hệ quản trị cơ sở dữ liệu.
- Chức năng cụ thể:
  + Complex Queries: Sử dụng JOIN, Subqueries (để đếm số chuyến đi), và Aggregate functions (`SUM`, `COUNT`, `AVG`).
  + JSON Functions: Sử dụng `json_build_object` để trả về dữ liệu quan hệ phức tạp trong một lần query duy nhất.
- Ví dụ trong Project:
  + Trong API `GET /api/admin/drivers/[id]`, query sử dụng Subquery để đếm tổng số chuyến đi của tài xế:
    ```sql
    SELECT d.*, 
      (SELECT COUNT(*) FROM rides WHERE driver_id = d.id) as total_rides
    FROM drivers d WHERE id = $1
    ```
  + Trong API `GET /api/admin/rides/[id]`, sử dụng `json_build_object` để trả về thông tin tài xế và người dùng trong một object JSON lồng nhau:
    ```sql
    SELECT r.*, 
      json_build_object('driver_id', d.id, 'first_name', d.first_name) as driver,
      json_build_object('clerk_id', u.clerk_id, 'name', u.name) as user
    FROM rides r
    INNER JOIN drivers d ON r.driver_id = d.id
    INNER JOIN users u ON r.user_id = u.clerk_id
    ```
  + Hàm `executeSql()` trong `src/lib/db.ts` sử dụng parameterized queries ($1, $2,...) để bảo vệ khỏi SQL Injection.
